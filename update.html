Evergreen Rebase / Repave

Evergreen evolves from a triggered repave path into the firm’s continuous base-image maintenance control plane: continuously establishing environment truth, maintaining supported base-image currency, staging blast radius, honoring bounded user intent, and protecting shared execution capacity.

Mandate

Routine currency

Centralize supported patch/minor maintenance while keeping major migrations in normal application SDLC.

Mechanics

Continuous fleet flow

Weekly image releases feed a durable maintenance backlog; components consume the newest eligible image when due.

Safety

Bounded automation

Rollout rings, deferral, pause, force, capacity limits, and production safeguards keep automation controlled.

Evergreen mandate

Automate repeatable maintenance; leave architectural migration with application teams.

Evergreen-owned

Patch + supported minor maintenance

  • Base-image discovery and desired-image catalog
  • Rebase/build automation
  • Environment repave orchestration
  • Maintenance cadence and exception governance
  • Operational pause/resume/force controls
Application-owned

Major / breaking migrations

  • Major runtime or framework upgrades
  • Breaking compatibility changes
  • Feature-driven architecture work
  • Normal planning, testing and SDLC timelines

Deferral becomes maintenance debt

Deferral is a bounded user choice; Evergreen retains responsibility for eventual remediation.

Governance

EXCEPTION

At the hard limit the item is visible and execution-eligible under mandatory policy unless paused or blocked.

Recommended runtime source of truth: Evergreen UI/API or control service. Keep evergreen.yml for durable configuration rather than ephemeral deferral state.

Evergreen control plane

Operational controls must be centralized and auditable — independent from repo commits.

Pause

Stop new admission

Scope to component, application, LOB, or firm; target rebase, repave, or all execution.

Resume

Return to policy

Re-enter normal ring, deferral, and scheduling rules.

Force

Emergency override

Bypass deferral and normal ring timing for critical remediation while preserving hard safety limits.

Control record

actor • reason • scope • phase • createdAt • expiresAt • approval/audit reference

Important distinction

Deferral is application-owned temporary intent. Pause/Force are platform operational controls.

Production adds safeguards

Production follows the same state model, but validation and governance happen before the production environment is touched.

1 · Rebase

Build application image on desired base.

2 · Validation environment

Deploy production code/config against desired base.

3 · Execute tests

Run application-defined validation.

4 · Create change

Prepare governed production change.

5 · Wait for window

Hold until production timing is approved.

6 · Repave + validate

Update production and confirm health.

Introduce every new architectural layer in compatibility mode before moving responsibility into it.

Combined takeaway

Evergreen centrally owns routine base-image currency. New images may arrive weekly, but the fleet consumes them continuously through a bounded maintenance cadence. Lower-blast-radius workloads establish confidence first, critical applications follow, teams may temporarily defer within policy, and Evergreen retains centralized controls to pause or accelerate execution when operational or security conditions demand it.
